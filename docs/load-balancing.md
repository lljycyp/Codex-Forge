# 实验性账号负载均衡

设置页的「账号负载均衡」默认关闭。开启后仅启动本机网关，不修改现有 Codex 配置、登录或进程。网关复用账号管理中的 ChatGPT 账号，使用可用账号中当前并发最少的账号；并发相同则轮流分配，同一会话不固定账号。每个真实账号最多同时处理两个请求，重复导入不增加容量。

## 接入

推荐使用设置页的「启动负载均衡客户端」按钮。Forge 自动准备独立的 `CODEX_HOME`、桌面用户数据目录和进程环境变量，不需要手动粘贴 Key，也不复制 ChatGPT 登录凭据。独立目录位于 `%LOCALAPPDATA%/CodexForge/load-balancer-client`，会话历史会保留；重复点击不会重启已打开的独立实例。独立客户端与原客户端的插件及设置不共享。首次启动只继承默认模型，之后保留独立客户端中选择的模型和桌面设置。

“运行中”只表示网关启动成功；出现成功请求后才表示转发链路已验证。关闭网关后该独立客户端无法继续请求，但窗口和历史不删除。

手动接入其他客户端：

1. 在设置页开启开关，检查账号状态。
2. 复制 Base URL 和 Key。Key 是 Forge 网关凭据，不是 OpenAI API Key。
3. 将「复制配置片段」中的设置合并到目标 Codex 配置，不要覆盖原文件。保留需要使用的模型。
4. 在该客户端的进程环境变量 `FORGE_GATEWAY_KEY` 中设置复制的 Key，再启动独立测试客户端。仅在默认登录框输入 Key 不会自动配置网关地址。

默认地址为 `http://127.0.0.1:19380/v1`。如果端口被占用，网关启动失败并显示错误，不会终止占用端口的进程。Key 使用当前 Windows 用户的 DPAPI 加密保存，不进入普通状态或请求日志。

开关关闭后停止接收新请求，已经开始的请求继续结束。退出 Forge 会停止网关并中断未完成请求；关闭窗口留在托盘时继续运行。启用状态会保存，下一次启动 Forge 自动恢复网关。关闭功能不会自动修改此前手工配置的客户端；需要手动恢复原来的模型服务配置。

## 支持范围

- 支持 `POST /v1/responses`，要求 `stream=true`、`store=false`，携带完整的 `input` 历史。
- 仅支持已有 ChatGPT 登录凭据；API Key 账号不会加入调度。
- 工具结果和加密推理内容原样转发；已验证客户端通过普通 Responses 请求生成文本摘要的压缩流程，压缩后仍可跨账号继续。
- 暂不支持 WebSocket、`previous_response_id`、服务端 conversation、文件 ID、服务端 `compaction` 块及 `/responses/compact`；明确报错，不隐藏固定账号、不丢弃字段。不同账号或模型是否接受加密内容仍取决于上游，上游拒绝时如实报错。
- 不提供 `/models` 列表或动态模型能力探测，客户端需指定账号支持的模型。
- 所有账号满载时返回 503，不在后台无限排队。
- 不自动重放失败请求。上游限流按恢复时间冷却；认证错误和临时上游错误短暂冷却。上游 HTTP 200 后流中断仍记录为失败。
- 只读取现有访问令牌，不刷新、不写回认证文件。令牌过期后通过现有「刷新额度」或重新授权更新。运行中的其他客户端使用量无法完整统计。
- 请求记录仅在网关进程内保留最近 30 条元数据，不保存提示词、附件、访问令牌或网关 Key。

订阅账号轮换可能涉及服务使用限制及账号停用风险；负载控制不能保证账号安全。

## 验证边界

自动测试使用临时数据库、临时账号文件、随机本地端口和模拟上游，覆盖认证、实际 HTTP 转发、并发选择、禁用、冷却、错误清理、后台进程生命周期、独立启动配置和原配置保护。真实验收结果见 [验收记录](load-balancing-validation.md)。
