# 负载均衡与局域网共享

在左侧栏底部选择「负载均衡」后，Forge 会自动准备本机网关的地址、证书和认证，并启动本机监听。配置成功后，在首页点击「使用负载均衡启动」打开 Codex。系统 Codex 使用文件存储的 ChatGPT 登录时，本机实例沿用该登录。其他环境使用本机专用的 Forge API Key。网关使用账号管理里的可用账号处理模型请求。首次使用默认是「指定账号」。

## 保留本机旧会话

首页使用系统安装的 Codex 客户端、内置 `openai` 提供方及原有的本机会话文件和历史数据库。沿用 ChatGPT 登录时，Forge 在启动前按账号切换流程载入共享分区、项目和排序。Codex 原生侧栏负责选中、运行和未读状态。使用本机 Key 时，Forge 在独立目录准备认证，Codex 显示原生项目列表。两种本机认证都只接入回环入口。目标客户端正在运行时，等手头任务结束后退出，再从首页切换模式。

切回「指定账号」后，下一次正常启动使用原连接设置。已验证的本机环境为 Windows、Codex Desktop 26.1111.2228.0，默认 OpenAI 提供方和文件登录。更早的桌面版本可能没有启动时覆盖地址的能力，Forge 会在启动前检查。自定义提供方可手动使用管理页的接入配置。

打开 Forge 时，换肤功能只连接已有的受管调试端口。如果已启用换肤，下次从首页启动 Codex 时会一并加载皮肤。

## 给局域网使用者发放 Key

1. 在 Forge 左侧打开「负载均衡」，选一块同事可以访问的局域网网卡和端口，开启「局域网共享」。
2. 点击「创建 Key」，填写使用者和有效天数，再输入并发上限或勾选「不限制」。保存首次显示的完整 Key。
3. 点击「导出 Codex 接入包」，把 ZIP 和该使用者的 Key 分开交给对方。ZIP 可以重复分发，包含当前局域网地址和 Forge 公共证书。
4. 对方在安装了原版 Codex 的 Windows 电脑上解压整个 ZIP，完全退出 Codex，然后双击 `Apply-Forge-Gateway.cmd`。它会验证 Forge 的 HTTPS 入口，通过 Codex 自己的配置接口设置用户级 `openai_base_url`，并为该 Windows 用户设置 `CODEX_CA_CERTIFICATE`。遇到已有自定义网关、提供方或其他 CA 配置时，会提示先核对现有设置。
5. 看到配置成功后，从平时的入口打开 Codex。若已登录其他账号，先退出，再选 API Key 登录并粘贴个人 Key。发一条消息，在 Forge 的「最近请求」确认对应使用者有成功记录。

需要恢复时，先在 Codex 退出 API Key 登录，完全关闭 Codex，再双击包中的 `Restore-Codex-Settings.cmd`。工具只恢复自己设置的网关地址和证书变量。重新配置同一个网关可使用原包，切换到另一地址或 CA 前先恢复。

### 手动接入

点击「复制客户端配置」，将配置片段合并到 `config.toml`，保留已有模型设置。解压接入包，启动 Codex 前设置 `FORGE_GATEWAY_KEY`，并将 `CODEX_CA_CERTIFICATE` 设为接入方电脑上 `forge-gateway-ca.pem` 的绝对路径。

```powershell
$env:FORGE_GATEWAY_KEY = '<自己的 Forge Key>'
$env:CODEX_CA_CERTIFICATE = 'C:\Forge\forge-gateway-ca.pem'
codex
```

本机默认监听 `https://127.0.0.1:19380/v1`。共享使用所选网卡的 HTTPS/WSS 地址，默认端口 19381。防火墙须允许同一局域网访问该 TCP 端口。管理操作通过本机 Forge 完成。停止局域网共享后，本机仍可使用网关。Forge 留在托盘期间继续提供服务，退出后停止接收请求。

Forge Key 只控制谁能接入这台网关。OpenAI 的个人账户条款禁止把账号提供给其他人使用，也禁止绕过限额，违规可能导致账号停用。给同事发 Key 前，请确认参与调度的上游账号或 API 项目获准供这些人使用。[OpenAI 账户共享说明](https://help.openai.com/en/articles/10471989-openai-account-sharing-policy) · [OpenAI 使用条款](https://openai.com/policies/terms-of-use/)

## 账号与请求

账号页继续负责授权和额度刷新。负载均衡页可调整参与状态和账号并发上限。网关读取已保存的凭证及同一身份较新的运行凭证，跳过无效授权、已知额度耗尽、冷却和重复身份。支持 Codex 登录、官方 OpenAI API Key，以及有明确部署名称的 Azure OpenAI v1 资源。

同一使用者和模型下，会话优先使用上次成功生成的账号，客户端重连后也适用。原账号无可用并发、额度不足或不支持该模型时，立即从其他可用账号里选择并发占用比例最低的账号，同负载时选择最久未被分配的账号。没有会话标识时直接使用这套排序。网关进程重启后重新记录会话偏好。已创建的局域网 Key 可在「访问 Key」中点击「编辑」调整并发上限。选择「不限制」时，调度仍受上游账号的并发上限和等待队列约束。等待队列按使用者轮流放行，分配账号前最长等待 25 秒。

ChatGPT 订阅账号的周额度或 5 小时额度剩余超过 1% 且不超过 2% 时，同一账号一次只接一个请求，请求结束后立即复查额度。任一适用窗口剩余 1% 或更低时暂停派发，已开始的请求继续处理。自动或手动刷新确认各适用窗口均超过 1% 后恢复调度，刷新失败时继续等待。

## 回答中途遇到额度限制

使用 ChatGPT Team（现称 Business）或个人订阅登录时，一次进行中的回答始终使用原席位。收到明确的可恢复额度错误后，Forge 保留当前问题、已完成的上下文和已经显示的文字，等候上游给出的恢复时间，再用原席位续写。没有恢复时间时，首次等待 60 秒，后续逐步延长至 15 分钟。工作区已开通共享点数时，点数及消费上限仍由上游执行。[Business 点数与消费控制](https://help.openai.com/en/articles/20001155-managing-credits-and-spend-controls-in-chatgpt-business)

等待期间「负载均衡 → 参与调度的账号」会显示「等待额度恢复后续写」。请保持 Forge 和该次请求的连接开启。等待占用这次请求原有的并发名额，可在 Codex 中随时停止。访问 Key 被撤销、席位被禁用或连接断开时，网关会释放名额。若原席位凭证在等待中到期，账号管理更新同一身份的登录后即可继续。退出 Forge 会结束正在等待的请求。

续写沿用原回答和消息 ID，只追加后续文字。Forge 会去掉衔接处可识别的逐字重复，重新生成的后半段仍可能有措辞差异。当本轮已经发出工具调用而执行结果尚未确认时，Forge 会交回上游错误，避免重复执行命令或写文件。权限错误、账单硬限制和普通网络断开也会直接交回错误。

### 团队 API 部署

单独使用 Azure OpenAI 的团队可以在已有 API 账号的 TOML 里登记同一资源、同一模型的主备部署。客户端请求的模型名使用主部署名。示例中的资源和部署名需要替换成自己的值。

```toml
model = "primary"
model_provider = "azure"

[model_providers.azure]
name = "Team Azure"
wire_api = "responses"
base_url = "https://RESOURCE.openai.azure.com/openai/v1"
http_headers = { x-ms-spillover-deployment = "secondary" }
```

上游明确报告主部署的限流时，Forge 使用原资源地址和原 API 凭证，在已登记的备用部署上续写。组织或工作区限额、作用范围不明的限流均留在原部署等待。备用部署本身的配额与费用由云端执行。[Azure 部署配额](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/quota)

## 支持的协议与状态

| 能力 | 行为 |
| --- | --- |
| HTTP 与 WebSocket | 支持 Responses 流式事件、非流式 HTTP 返回、WS 多轮和取消。连接内一次处理一个生成。同一客户端连接里的后续请求，在账号和模型相同时可复用上游 WebSocket。 |
| 服务端续接 | 用返回的 `previous_response_id` 取回该使用者的输入和输出，补齐上下文后重新调度。写入空间不足时，新快照仅可淘汰同一使用者最早的响应快照。快照缺失时返回 `previous_response_not_found`，客户端需提供完整历史。 |
| 文件 | 通过 `POST /v1/files` 上传后可引用 Forge 文件 ID。对支持的输入格式，网关将原始字节作为内联文件或图片交给上游。已实测 PDF。 |
| 服务端压缩 | 兼容 Responses 中的压缩事件和 `/v1/responses/compact`。对 Codex 登录账号，后者使用远端压缩生成，返回上游的加密压缩块。 |
| 访问隔离 | 每个 Key 有稳定的使用者 ID。轮换保留其资源，撤销删除其临时文件和响应链。其他 Key 无法读取这些 ID。 |

文件上传上限为 16 MiB。临时文件和续接内容使用当前 Windows 用户的 DPAPI 加密，逻辑有效期 24 小时，另有单项、每人和总存储限制。完整会话仍由使用者自己的 Codex 管理。原服务独有的会话 ID、外部文件 ID、托管工具资源不能直接迁入。上游模型对文件和加密状态的支持可能因账号和版本而异。

页面保留最近 100 条生成记录，显示来源、账号、协议、结果、输入 Token、缓存命中 Token、输出 Token 和续写次数，不记录提示词或上游凭证。缓存命中 Token 已包含在输入 Token 中。未报告的用量显示为「未知」。同一次请求的多次尝试按上游已报告的用量累加。

## 本次实测

2026-11-19，在独立工作树和临时客户端环境验证。复制了一条已有本机任务，在隔离桌面侧栏打开它，然后从同一任务追问最初的问题。桌面回答与历史一致。另用同版本 App Server 在同一旧会话副本连续追问两次，两次均答对，网关依次记录两个不同账号的 WebSocket 生成完成事件。

实际在本机局域网 IPv4 地址上使用 HTTPS/WSS 和两个 Key，验证了 PDF 原文识别、跨账号续接、跨 Key 文件及响应隔离、撤销后返回 401、其他 Key 继续调用，以及真实加密压缩块在另一账号下续聊。局域网客户端和服务位于同一台测试主机，另一台物理电脑的防火墙与证书配置需要在目标网络验证。

另用独立配置启动本机 Codex 命令行客户端，在 WebSocket 回答输出半句后由本地注入一次额度错误和 1 秒恢复时间。续写请求使用同一真实 Team 席位，客户端只收到一条完整回答。中断和恢复时间由测试控制，未消耗订阅至真实限额。Azure 主备部署、连续两次中断、工具保护、取消和撤销 Key 使用隔离模拟上游验证。
